# bbb-mp4-simple

Разовый запуск оригинального образа [manishkatyan/bbb-mp4](https://github.com/manishkatyan/bbb-mp4) с готовым URL записи BigBlueButton 2.3. Chrome в контейнере открывает переданный URL напрямую; адрес BBB из имени домена и ID не собирается. VM с Docker и сервер BBB могут находиться на разных машинах, но контейнеру необходим сетевой доступ к URL и связанным ресурсам записи.

## Установка на Ubuntu VM

Docker уже должен быть установлен; пользователь, запускающий команды, должен иметь право пользоваться Docker. Нужны Python 3 и systemd (стандартные компоненты Ubuntu), а для установки systemd-сервиса — root или sudo. Выполните после создания VM:

```bash
curl -fsSL https://raw.githubusercontent.com/vsesem-git/bbb-mp4-simple/main/deploy.sh -o deploy.sh
bash deploy.sh
cd ~/bbb-mp4-simple
```

Ссылка выше работает после публикации изменений в `main`. Также можно сначала клонировать нужную ветку репозитория и запустить `./deploy.sh` из неё. Скрипт подготовит каталог `recordings`, создаст `.env` с абсолютным путём `COPY_TO_LOCATION`, скачает оригинальный Docker-образ и установит и запустит systemd-сервис `bbb-mp4-web`. Он будет автоматически запускаться после перезагрузки VM от имени пользователя, выполнившего развёртывание.

Повторный запуск сохраняет существующий `.env` и файлы, не обновляет и не сбрасывает существующий checkout, но **перезапускает веб-сервис**. Не запускайте развёртывание во время конвертации. Если нужен другой каталог результатов, измените `COPY_TO_LOCATION` в `.env` (это shell-файл, путь с пробелами нужно заключить в кавычки) и повторите `./deploy.sh`.

## Веб-интерфейс

Откройте в браузере `http://<IP-VM>:8080` с компьютера в доверенной сети. Вставьте полный playback URL и нажмите «Добавить задание». Таблица показывает очередь, этап (подготовка, запись, финализация, проверка), приблизительный прогресс и оставшееся время, а также размер и длительность готового файла. Доступны поиск по ID или ссылке и фильтр по статусу. По нажатию на превью скриншот открывается крупно; кнопка «Журнал» показывает последние сообщения задания. Одновременно выполняется одно задание; остальные ожидают в порядке добавления. Превью снимается внутри контейнера при появлении изображения и затем примерно раз в минуту. Если скриншот пока недоступен, отображается прочерк.

В очереди задание можно убрать, выполняющееся — остановить. После остановки можно удалить запись из списка. У готового задания доступны скачивание, удаление и пересоздание. **Удаление удаляет и соответствующий MP4 с диска**; перед удалением потребуется подтверждение. **При пересоздании прежний MP4 удаляется сразу после подтверждения**, ещё до запуска. Если новое задание завершится ошибкой или будет остановлено, прежний файл не восстановится. Не запускайте одновременно обработку одной записи вручную через `convert.sh` и через веб-интерфейс.

Задания, ссылки и последнее превью сохраняются в `state/` на VM. Этот каталог может содержать URL с токенами и доступен только пользователю сервиса. Настройки и последние 16 000 символов журнала каждого задания также сохраняются там; журналы могут содержать данные записи. Если Chrome/FFmpeg аварийно завершились или полученный файл не прошёл проверку, выполняются до двух автоматических повторов (три попытки всего) с задержками 5 и 10 секунд. Явно обнаруженная отсутствующая запись, неподходящий кодек/разрешение и ошибки инфраструктуры Docker повторно не запускаются. Ожидание повтора можно остановить; параметры не меняются. После перезапуска ожидающие задания продолжат выполняться, а прерванное задание будет помечено остановленным; его можно пересоздать. При первом запуске этой версии уже имеющиеся в каталоге результатов MP4 появятся в списке. Поскольку прежняя версия не сохраняла URL, для пересоздания таких файлов нужно заново вставить playback URL в форму.

### Настройки конвертации

В разделе «Глобальные настройки конвертации» выбираются режим, разрешение, битрейт видео и аудио (кбит/с) и пресет. Для новой установки значения по умолчанию: **совместимость H.264, 1280×800, видео auto, аудио 128 кбит/с, medium**. В режиме auto используются H.264 CRF 22 или H.265 CRF 26; вместо auto можно указать битрейт видео числом. Второй режим — **максимальное сжатие H.265**; он требует больше процессорного времени и поддерживается не всеми устройствами и браузерами.

Для отдельного нового задания можно переопределить любое значение в форме добавления. В поле битрейта этого задания пустое значение означает использовать глобальное, `auto` — выбрать CRF. Настройки фиксируются при создании задания: изменения глобальных значений не влияют на уже созданные задания или их пересоздание. Существующие сохранённые глобальные настройки и задания после обновления сохраняют прежние значения; для них автоматически выбирается H.264. Если ранее сохранялся числовой битрейт (например, 2500 кбит/с), переключите его на `auto` вручную, чтобы использовать CRF.

Chrome и Xvfb работают с исходным экраном 1280×800. Выбранное разрешение применяется к видео: изображение масштабируется с сохранением пропорций, при необходимости добавляются чёрные поля. Увеличение разрешения выше исходного не добавляет детализации и может увеличить файл. При числовом битрейте видео значение передаётся через `-b:v`, аудио — через `-b:a`. Обычный вызов `convert.sh` использует настройки оригинального образа.

H.265 и более медленный пресет часто уменьшают размер, но **меньший размер и полное отсутствие потери качества одновременно гарантировать нельзя**: CRF — сжатие с потерями, а результат зависит от записи. Значения CRF разных кодеков не равнозначны; H.265 CRF 26 может отличаться по качеству от H.264 CRF 22. Сравните качество и размер на ваших записях; если важнее качество и совместимость, используйте H.264 и исходное разрешение.

### Проверка и диагностика

После записи проверяются формат, длительность, наличие видео- и аудиодорожки, разрешение и кодек, затем видео и аудио полностью декодируются без сохранения. Если длительность исходной записи известна, результат проверяется на преждевременное завершение с допуском 2 секунды или 1% длительности (что больше). На длинных записях проверка потребляет процессор и может занять дополнительное время. Она выявляет ошибки декодирования, но не гарантирует, что звук не является тишиной или что изображение содержит нужный материал. Файлы, созданные до обновления, автоматически не проверяются.

Веб-интерфейс показывает свободное место на файловой системе **каталога результатов**. При менее чем 1 ГиБ перед добавлением или пересозданием задания запрашивается подтверждение; это предупреждение, а не оценка требуемого размера. Временные файлы оригинального контейнера также занимают место в хранилище Docker, которое может находиться на другой файловой системе и этой проверкой не охватывается.

Прогресс рассчитывается по длительности записи и времени с начала захвата, поэтому является **приблизительным**. Пока оригинальный конвертер не определил длительность и не начал захват, время и прогресс неизвестны; на этапах финализации и проверки оставшееся время не оценивается. Причина сбоя и последние сообщения доступны в кнопке «Журнал» строки задания. Общий журнал сервиса:

```bash
journalctl -u bbb-mp4-web -n 100 --no-pager
```

**Безопасность:** входа по паролю и HTTPS нет. Любой, кто получит доступ к интерфейсу, сможет запускать и останавливать конвертацию, просматривать превью и скачивать или удалять файлы. Сервис слушает все интерфейсы на порту 8080 и принимает соединения только с IPv4-адресов RFC 1918 и localhost. Дополнительно ограничьте доступ сетевым экраном VM/Proxmox только доверенной подсетью; не публикуйте сервис в интернете и не размещайте его за публичным прокси. Ссылки на скачивание работают только там, где доступен адрес VM.

## Конвертация из командной строки

```bash
./convert.sh "https://vks.vsesem.ru/playback/presentation/2.3/f678f4a23ecaf2ac77135e744f2c9da8764c32dd-1793270594439"
```

Команда принимает один полный HTTP(S) playback URL формата, поддерживаемого оригиналом: `/playback/presentation/2.3/<40 строчных букв или цифр>-<13 цифр>`. Query string и fragment передаются без изменений. По умолчанию результат находится в `recordings/<meeting_id>.mp4` на VM, а не на сервере BBB. Скрипт работает в переднем плане до завершения контейнера. Контейнер работает с правами по умолчанию оригинального образа, поэтому созданные им файлы могут принадлежать root.

Конвертация использует оригинальный образ Chrome/Xvfb/FFmpeg. Для заданий веб-интерфейса в контейнер подключается адаптированный скрипт FFmpeg (`ffmpeg-cmd.sh`, лицензия оригинала — `LICENSE.upstream`); требования к странице playback и ограничения оригинального конвертера сохраняются. Никаких изменений на сервере BBB или в post_publish не производится.
