# bbb-mp4-simple

Разовый запуск оригинального образа [manishkatyan/bbb-mp4](https://github.com/manishkatyan/bbb-mp4) с готовым URL записи BigBlueButton 2.3. Chrome в контейнере открывает переданный URL напрямую; адрес BBB из имени домена и ID не собирается. VM с Docker и сервер BBB могут находиться на разных машинах, но контейнеру необходим сетевой доступ к URL и связанным ресурсам записи.

## Установка на Ubuntu VM

Docker уже должен быть установлен; пользователь, запускающий команды, должен иметь право пользоваться Docker. Нужны Python 3 и systemd (стандартные компоненты Ubuntu), а для установки systemd-сервиса — root или sudo. Выполните после создания VM:

```bash
curl -fsSL https://raw.githubusercontent.com/vsesem-git/bbb-mp4-simple/main/deploy.sh -o deploy.sh
bash deploy.sh
cd ~/bbb-mp4-simple
```

Ссылка выше работает после публикации изменений в `main`. Также можно сначала клонировать нужную ветку репозитория и запустить `./deploy.sh` из неё. Скрипт подготовит каталог `recordings`, создаст `.env` с абсолютным путём `COPY_TO_LOCATION`, скачает оригинальный Docker-образ и установит и запустит systemd-сервис `bbb-mp4-web`. Он будет автоматически запускаться после перезагрузки VM от имени пользователя, выполнившего развёртывание.

Повторный запуск сохраняет существующий `.env` и файлы, не обновляет и не сбрасывает существующий checkout, но **перезапускает веб-сервис**. Не запускайте развёртывание во время конвертации. Если нужен другой каталог результатов, измените `COPY_TO_LOCATION` в `.env` (это shell-файл, путь с пробелами нужно заключить в кавычки) и повторите `./deploy.sh`.

## Веб-интерфейс

Откройте в браузере `http://<IP-VM>:8080` с компьютера в доверенной сети. Вставьте полный playback URL и нажмите «Добавить задание». Таблица показывает очередь, этап (подготовка, запись, финализация, проверка), приблизительный прогресс и оставшееся время. Доступны поиск по ID или ссылке и фильтр по статусу. По нажатию на превью скриншот открывается крупно; кнопка «Журнал» показывает последние сообщения задания. Одновременно выполняется одно задание; остальные ожидают в порядке добавления. Превью снимается внутри контейнера при появлении изображения и затем примерно раз в минуту. Если скриншот пока недоступен, отображается прочерк.

В очереди задание можно убрать, выполняющееся — остановить. После остановки можно удалить запись из списка. У готового задания доступны скачивание, удаление и пересоздание. **Удаление удаляет и соответствующий MP4 с диска**; перед удалением потребуется подтверждение. При пересоздании прежний MP4 сохраняется до успешного завершения новой конвертации и затем заменяется. Не запускайте одновременно обработку одной записи вручную через `convert.sh` и через веб-интерфейс.

Задания, ссылки и последнее превью сохраняются в `state/` на VM. Этот каталог может содержать URL с токенами и доступен только пользователю сервиса. Настройки и последние 16 000 символов журнала каждого задания также сохраняются там; журналы могут содержать данные записи. После перезапуска ожидающие задания продолжат выполняться, а прерванное задание будет помечено остановленным; его можно пересоздать. При первом запуске этой версии уже имеющиеся в каталоге результатов MP4 появятся в списке. Поскольку прежняя версия не сохраняла URL, для пересоздания таких файлов нужно заново вставить playback URL в форму.

### Настройки конвертации

В разделе «Глобальные настройки конвертации» выбираются разрешение, битрейт видео и аудио (кбит/с) и пресет кодирования. Изначальные значения: **1280×800, 2500 кбит/с, 128 кбит/с, fast**. Для отдельного нового задания можно переопределить любое из значений в форме добавления. Настройки фиксируются при создании задания: последующее изменение глобальных значений не влияет на уже созданные задания, включая их пересоздание. Задания, созданные до появления настроек, сохраняют прежние параметры оригинального образа.

Chrome и Xvfb по-прежнему работают с экраном 1280×800. Выбранное разрешение применяется к готовому видео: изображение масштабируется с сохранением пропорций, при необходимости добавляются чёрные поля. Битрейт видео передаётся FFmpeg через `-b:v`, аудио — через `-b:a`. Эти настройки относятся к заданиям веб-интерфейса; обычный вызов `convert.sh` сохраняет настройки оригинального образа.

### Проверка и диагностика

После записи проверяются формат, длительность, наличие видео- и аудиодорожки и разрешение, затем видео и аудио полностью декодируются без сохранения. На длинных записях проверка потребляет процессор и может занять дополнительное время. Она выявляет ошибки декодирования, но не гарантирует, что звук не является тишиной или что изображение содержит нужный материал. Файлы, созданные до обновления, автоматически не проверяются.

Веб-интерфейс показывает свободное место на файловой системе **каталога результатов**. При менее чем 1 ГиБ перед добавлением или пересозданием задания запрашивается подтверждение; это предупреждение, а не оценка требуемого размера. Временные файлы оригинального контейнера также занимают место в хранилище Docker, которое может находиться на другой файловой системе и этой проверкой не охватывается.

Прогресс рассчитывается по длительности записи и времени с начала захвата, поэтому является **приблизительным**. Пока оригинальный конвертер не определил длительность и не начал захват, время и прогресс неизвестны; на этапах финализации и проверки оставшееся время не оценивается. Причина сбоя и последние сообщения доступны в кнопке «Журнал» строки задания. Общий журнал сервиса:

```bash
journalctl -u bbb-mp4-web -n 100 --no-pager
```

**Безопасность:** входа по паролю и HTTPS нет. Любой, кто получит доступ к интерфейсу, сможет запускать и останавливать конвертацию, просматривать превью и скачивать или удалять файлы. Сервис слушает все интерфейсы на порту 8080 и принимает соединения только с IPv4-адресов RFC 1918 и localhost. Дополнительно ограничьте доступ сетевым экраном VM/Proxmox только доверенной подсетью; не публикуйте сервис в интернете и не размещайте его за публичным прокси. Ссылки на скачивание работают только там, где доступен адрес VM.

## Конвертация из командной строки

```bash
./convert.sh "https://vks.vsesem.ru/playback/presentation/2.3/f678f4a23ecaf2ac77135e744f2c9da8764c32dd-1793270594439"
```

Команда принимает один полный HTTP(S) playback URL формата, поддерживаемого оригиналом: `/playback/presentation/2.3/<40 строчных букв или цифр>-<13 цифр>`. Query string и fragment передаются без изменений. По умолчанию результат находится в `recordings/<meeting_id>.mp4` на VM, а не на сервере BBB. Скрипт работает в переднем плане до завершения контейнера. Контейнер работает с правами по умолчанию оригинального образа, поэтому созданные им файлы могут принадлежать root.

Конвертация использует оригинальный образ Chrome/Xvfb/FFmpeg. Для заданий веб-интерфейса в контейнер подключается адаптированный скрипт FFmpeg (`ffmpeg-cmd.sh`, лицензия оригинала — `LICENSE.upstream`); требования к странице playback и ограничения оригинального конвертера сохраняются. Никаких изменений на сервере BBB или в post_publish не производится.
