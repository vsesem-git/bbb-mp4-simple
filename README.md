# bbb-mp4-simple

Разовый запуск оригинального образа [manishkatyan/bbb-mp4](https://github.com/manishkatyan/bbb-mp4) с готовым URL записи BigBlueButton 2.3. Chrome в контейнере открывает переданный URL напрямую; адрес BBB из имени домена и ID не собирается. VM с Docker и сервер BBB могут находиться на разных машинах, но контейнеру необходим сетевой доступ к URL и связанным ресурсам записи.

## Установка на Ubuntu VM

Docker уже должен быть установлен; пользователь, запускающий команды, должен иметь право пользоваться Docker. Выполните после создания VM:

```bash
curl -fsSL https://raw.githubusercontent.com/vsesem-git/bbb-mp4-simple/main/deploy.sh -o deploy.sh
bash deploy.sh
cd ~/bbb-mp4-simple
```

Также можно сначала клонировать репозиторий и запустить `./deploy.sh` из него. Скрипт подготовит каталог `recordings`, создаст `.env` с абсолютным путём `COPY_TO_LOCATION` и скачает оригинальный Docker-образ. Повторный запуск сохраняет существующий `.env` и файлы, не обновляет и не сбрасывает существующий checkout. Если необходим другой каталог результатов, измените `COPY_TO_LOCATION` в `.env` (это shell-файл, путь с пробелами нужно заключить в кавычки) и повторите `./deploy.sh`.

## Конвертация

```bash
./convert.sh "https://vks.vsesem.ru/playback/presentation/2.3/f678f4a23ecaf2ac77135e744f2c9da8764c32dd-1793270594439"
```

Команда принимает один полный HTTP(S) playback URL формата, поддерживаемого оригиналом: `/playback/presentation/2.3/<40 строчных букв или цифр>-<13 цифр>`. Query string и fragment передаются без изменений. По умолчанию результат находится в `recordings/<meeting_id>.mp4` на VM, а не на сервере BBB. Скрипт работает в переднем плане до завершения контейнера; демон и автозапуск не нужны. Контейнер работает с правами по умолчанию оригинального образа, поэтому созданные им файлы могут принадлежать root.

Конвертация использует оригинальную реализацию Chrome/Xvfb/FFmpeg, включая её требования к странице playback и ограничения. Никаких изменений на сервере BBB или в post_publish не производится.
